# エンジニアAI（外向け：AI改善提案）

業種・業務を入力すると、AIが「どの業務を、どんなツールで、どのくらいの手間で減らせるか」を提案し、選んだ案の試作品（その場で動くHTMLツール）まで作るツール。

shindan-checker（シゴト負荷チェック）とは**別システム**（2026-09-28 Owner判断：診断チェッカー本体には手を入れず、完全に独立したツールとして開発）。連携方法は未定。

## ファイル構成

- `index.html` / `kaigo/index.html` / `hoiku/index.html`：フロントエンドの入口ページ（見出し文と初期選択業種のみが違う。中身は共通）
- `app.js`：フロントエンドの共通ロジック（業種・役割選択、業務入力、AI提案、試作品生成・プレビュー・ダウンロード、個人/企業モード切り替え）
- `data.js`：業種・役割・時間・つらい理由の一覧（engineer-ai独自。shindan-checkerのデータは使わない）
- `styles.css`：共通スタイル
- `worker/`：Cloudflare Workers中継
  - `src/index.js`：Origin確認・ルーティング（`/`＝提案、`/prototype`＝試作品）・回数制限（種別ごとに分離）・`ANTHROPIC_API_KEY`があれば実API呼び出し／なければモック応答
  - `src/prompts.js`：提案用・試作品用システムプロンプト
  - `src/filter.js`：出力の禁止語チェック（二重の保険。試作品のhtml本文も対象）
- `system-prompt.md`：システムプロンプト2本（`worker/src/prompts.js`と同内容）
- `test-cases.md`／`verify-cases.mjs`：提案の架空ケース10件の検証結果とスクリプト
- `test-cases-prototype.md`：試作品の架空ケース検証結果

## 注意

- 禁止語リスト（`worker/src/filter.js`内`NG_WORDS`）は2026-09-29にmedical部門のレビュー済み。ただし試作品の判断機能禁止（基準値比較・警告等）はNG_WORDSでは防げないため、プロンプト側の指示に依存する。介護・保育向けの受託を本番化する前には、医療機器該当性（PMDA）・個人情報の扱い（弁護士）・記録の保存義務（自治体）の専門家確認が必要（`engineer-ai-spec.md`「v1.2」参照）
- `app.js`の`AI_RELAY_URL`は本番Worker URLを指している。**フロントエンドをローカルで動かすUIテストをするときは、一時的に`http://localhost:8787`に戻し、確認後に本番URLへ戻すこと**（本番Originチェックの都合上、localhostからは直接本番Workerを呼べない）
- `worker/.dev.vars`（git管理外）に本物のAPIキーを保存している。ローカルで`wrangler dev`すると実際にAnthropic APIを呼ぶので、テスト時はコール回数に注意
- Cloudflare KVのレート制限カウンタは日付キーで2日後に自動失効する。テストで消費した分を戻したい場合は`wrangler kv key delete <キー名> --namespace-id d68cdca97fb94c068c60f99f092f45ed --remote`で手動リセット可能
- `products/engineer-ai/`は独自のgitリポジトリ（company全体のリポジトリとは別）。v1.1完成時点でコミット済み、戻したい場合はそこまで`git log`で戻れる
